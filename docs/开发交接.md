# 看山开发交接

当前源码版本：0.6.8。浏览器扩展版本：0.9.0。此包用于接手开发，包含当前工作区的源码与素材，不依赖 Git 历史。

## 先运行

在 Windows 64 位系统安装 Node.js 22.19.0 或更高版本，在项目根目录执行：

```powershell
npm ci
npm start
```

首次安装需要联网下载 npm 依赖和 Electron。启动后桌宠出现在右下角，点击桌宠打开默认浏览器。网页服务地址是 `http://127.0.0.1:47840/`，桌宠退出后服务停止。开发版与打包版使用同一个端口，运行前退出另一版本。

无需创建 `.env`。在网页右上角“连接设置”填写自己的知乎 Access Secret、模型 API 根地址、模型名称和 API Key。联网搜索和模型调用需要这些服务可用；未配置时可以检查界面和本地问题记录。

在 Chrome 的 `chrome://extensions` 或 Edge 的 `edge://extensions` 中开启开发者模式，加载本项目的 `extension` 文件夹。加载或重新加载插件后刷新阅读伙伴网页，插件通过网页会话自动获取并验证本机凭证；设置页仅展示连接状态，不提供手动连接码。主动断开后暂停自动连接，可通过“恢复连接”或插件的打开网页按钮恢复。

## 文件从哪里看

| 文件 | 职责 |
| --- | --- |
| `main.cjs`、`preload.cjs` | Electron 窗口、IPC、托盘、拖拽、启动本机服务 |
| `reading-server.cjs`、`web.cjs` | 网页资源、接口路由、本机会话与鉴权 |
| `service.cjs` | 知乎搜索、凭证加密、本机摘录和问题数据、帖子反馈 |
| `agent.mjs` | pi Agent 的模型调用、超时和错误处理 |
| `features.cjs`、`interests.cjs`、`memory.cjs` | 问题标识同步、检索词生成、动态兴趣与阅读信号 |
| `ui/app.js` | 基础页面、问题完整记录、行动状态、反馈编辑、本地保存 |
| `ui/live.js` | 真实服务连接、推荐卡片、换一篇、模型建议及反馈调整 |
| `ui/experience.js` | 插件摘录同步、问题检索结果留存、兴趣设置 |
| `ui/style.css` | 网页样式 |
| `ui/pet.html`、`ui/pet.css`、`ui/pet.js`、`ui/pet-behavior.js` | 桌宠素材显示、动作、交互和待机调度 |
| `pet-*.cjs` | 桌宠设置、菜单、位置、抛掷与碎碎念 |
| `extension` | Manifest V3 浏览器扩展，含重连、划线、批注、问题关联 |
| `tests` | 单元、接口、页面、原生窗口与打包检查 |

网页脚本按 `app.js → live.js → experience.js` 顺序加载，共享部分状态和渲染函数。调整加载顺序、事件捕获或全局函数时，需要运行页面联调检查。新增网页静态资源时，需要同时更新 `reading-server.cjs` 的资源映射。

## 已实现的主要流程

- 点击桌宠打开网页；拖拽、贴边、托盘和右键菜单。
- 首页两张真实知乎推荐卡片，以及最新金句、最新问题两张卡片。
- 每个问题下保留找到的帖子、关联金句与批注、可编辑补充、行动建议。
- 每条行动支持“准备试试／试过了／不适合”和文字反馈。再次调整时发送当前行动及近期历史反馈，保留此前的建议。
- 推荐卡片单独“换一篇”，明确“不感兴趣”持久化为帖子反馈。
- 插件恢复已配对连接；由问题打开的帖子默认关联该问题；保存成功以桌宠小动作反馈。

## 用户已确认的设计约束

- 网页保留米白、墨色和橄榄绿，布局参考 Claude 官网：顶部导航、左侧角色与标题、右侧终端风搜索。整体内容宽度 920px，问题、摘录和连接设置的内列最大宽度 760px，页脚已移除。标题末尾不加句号；终端不显示“Search / 文章与回答”标签行。插件安装说明分成安装、连接两个实际步骤；不添加装饰性编号或重复说明。
- 首页保持四张卡片：“最近的摘录”和“正在探索”放在“今日阅读”标题之前，知乎推荐放在其后；不恢复已删除的“留到后来”和“阅读足迹”导航。
- 终端按用户参考图使用黑底、深灰窗口栏、红黄绿窗口按钮和紫蓝青绿文字。输入框不显示提示文字，空白时用青色方块光标闪烁提示；输入后使用原生文字光标。问题与摘录页副标题去掉句号，并向右缩进。
- 顶部主导航包含“我的偏好”；右侧“连接设置”使用无边框文字按钮。
- 动态兴趣开关开启时显示彩色渐变与加速环绕粒子，关闭后停止；跟随系统减少动态效果设置停用动效。
- 阅读偏好和连接设置是两个独立页面。阅读偏好只保留一个面板，兴趣用自适应宽度的可编辑标签，动态更新开关与保存按钮合并在底部；移除返回按钮、说明、近期关注列表和手动更新区。
- 摘录是 3:4 手账卡片，金句与批注用不同字体和颜色。
- 建议应像朋友给出的具体小步骤，避免冗长分析报告。
- 页面短提示用右下角的黑白看山角色配浅色对话气泡，替代深色通知条；文案自然简短，停留时间随文本长度调整。
- 智能体框架使用 pi；代码中不新增注释。
- 桌宠采用用户在阅读首页选定的黑白线稿看山形象（`ui/kanshan.png`），不能自行重新设计角色。
- 未经用户后续明确要求，不上传或公开发布项目。

## 数据与迁移注意

当前仍存在两处存储：

- 问题、找到的帖子、行动反馈、建议历史、手动兴趣等，在浏览器 `localStorage` 的 `kanshan-design-demo-v1` 中。
- 插件已保存摘录、服务端问题标识、不感兴趣反馈、加密凭证等，在当前 Windows 用户应用数据目录中；阅读服务使用 `reading-v0.6` 子目录。

保留现有字段和本地记录。修改问题的补充时应更新已有服务端问题，不能换新标识，否则插件关联会断开。统一存储与完整备份尚未实施，是后续可改善项。

凭证通过 Windows 加密保存，不能复制分享者的 `credentials.bin` 给其他人使用。此源码包不含运行数据、密钥、配对码和 Git 历史。测试中的 `synthetic-*`、`test-model` 等是模拟数据。

## 打包给用户

```powershell
npm run package
npm run test:package
python scripts/share.py
```

`npm run package` 生成 `release-v0.6/Kanshan-win32-x64`，输出目录名称目前是固定的，不随应用版本自动变化。已有同名输出时打包不会覆盖：先退出对应程序，将旧目录改名保留，再重新打包。

`scripts/share.py` 需要 Python 3，仅使用标准库。它从已经生成的运行目录创建带启动入口和使用说明的 Windows 分享包，并校验 ZIP。源码运行和 Electron 打包本身不需要 Python。

更新 `package.json` 版本时同步更新 `package-lock.json` 的根版本与 `packages[""]` 版本。分发时保留整个 Electron 运行目录与 `resources/extension`，不能只发 EXE。

当前用户偏好：后续仅检查桌面端，不执行手机端检查。页面联调可使用 `$env:KANSHAN_DESKTOP_ONLY='1'; npm run test:ui`。
